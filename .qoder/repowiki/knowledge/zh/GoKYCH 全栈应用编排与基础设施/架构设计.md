- **容器化编排**：利用 `docker-compose.yml` 统一管理 MySQL 数据库与 Go 后端的生命周期，通过健康检查（healthcheck）确保后端在数据库就绪后启动。
- **配置与环境契约**：根目录的 `.env` 文件作为跨模块共享的环境变量源，后端通过 `configs/` 和内部配置加载机制读取，前端通过 API 层间接依赖后端暴露的配置状态。
- **前后端交互边界**：确立了前端（Next.js）与后端（Gin）的物理隔离与逻辑耦合，前端通过统一的 API 客户端（`web/lib/api.ts`）与运行在 `8000` 端口的后端进行 RESTful 通信。
- **数据持久化策略**：通过 Docker Volumes (`mysql_data`, `app_data`) 统一管理数据库文件与应用运行时数据（如头像、设置），确保容器重启后状态不丢失。

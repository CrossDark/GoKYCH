# GoKYCH 项目优化建议

> 范围:Go 后端 + Next.js 前端。整体完成度约 80%。`docs/建议.md` 已列 15 项已知缺口(见附录 A),以下为**新增/深化**项。
> 标注「需复核」的因 `user.go`/`router.go`/`session.go` 全文在审查时多次读取异常,需实施时二次确认。
> 不改对外 URL 与 API 契约,保持 `重写.md` §7 验收标准不变。

---

## P0 — 立即(安全/数据完整性)

### 1. 启动日志泄露明文 admin 密码 — `internal/core/schema/schema.go:45`
```go
log.Printf("[schema] seeded admin user %q (password: %s)", username, password)
```
**问题**:明文密码进容器/systemd 日志,任何能读日志的人即拿到 owner 凭据。
**修复**:删除 `(password: %s)`,只打印用户名。

### 2. createUser 潜在垂直提权 — `internal/api/admin.go:55-89`
路由 `POST /api/admin/users` 仅 `requireAdmin`,而 `createUser` 用 `user.IsValidRole(in.Role)` 校验后直接 `user.Create(..., in.Role)`。若 `IsValidRole` 允许 `'owner'`(需复核),admin 可创建 owner 账号 → 绕过所有 `requireOwner` 限制。
**修复**:`createUser` 禁止 `role=='owner'`,仅允许 `user`/`admin`;admin 不得创建不弱于自己角色的用户。

### 3. User 结构可能泄露 password_hash — 需复核 `internal/auth/user/user.go`
`getMe`(`auth.go:71`)、`listUsers`、`createUser`(`admin.go:87` `c.JSON(http.StatusCreated, u)`)直接序列化 `user.User`。若 `PasswordHash` 字段未打 `json:"-"`,bcrypt 哈希会随 API 响应返回前端。
**修复**:确认 `PasswordHash string \`json:"-"\``,统一过滤敏感字段。

## P1 — 近期(安全加固 / 正确性 Bug)

### 4. ratings.score 缺 CHECK 约束 — `internal/core/schema/schema.go:127`
`score DECIMAL(4,2)` 允许 ±99.99,但 `重写.md` §3.3 要求 `[-1.00, 1.00]`。
**修复**:列定义加 `CHECK (score BETWEEN -1.00 AND 1.00)`,`setRating` API 层同步校验;已有数据先清洗。

### 5. 评论/评分用 author_name 字符串而非 user_id — `schema.go:111-132`
任何匿名用户可冒充他人(含 admin)发评论;换 author_name 即可重复评分(刷分),`uq_user_article(article_id, author_name)` 形同虚设。
**修复**:已登录用户绑定 `user_id`,`author_name` 仅作显示名;评分唯一键改 `(article_id, COALESCE(user_id, author_name))`。

### 6. clientIP 信任 X-Forwarded-For 首段 → 限流绕过 — `internal/api/middleware.go:120-130`
直连/未配反代时,客户端伪造 `X-Forwarded-For: 1.2.3.4` 即可每请求换 IP,登录 ratelimit 全失效。
**修复**:用 Gin `r.SetTrustedProxies(...)` + `c.ClientIP()`,删除手写 `clientIP` 或仅读 `RemoteAddr`。

### 7. crypto/rand.Read 错误被忽略 — `internal/auth/session/crypto.go:12`
```go
_, _ = rand.Read(b)
```
熵异常时 buffer 可能未填满 → CSRF/session token 含全零段可预测。
**修复**:检查 err,失败 `log.Fatal` 或重试。

### 8. 建表失败只 log 不中止启动 — `internal/core/schema/schema.go:11-17`
`Init` 失败仅 `log.Printf` 后继续,DB 异常时程序照常启动,后续查询全 500。
**修复**:建表失败 `return error`,`main.go` `log.Fatal`。

### 9. typst 子进程无超时 / 无并发上限 / 无缓存查询 — `internal/typst/typst.go:42-83`
每次 `MkdirTemp`+spawn typst,`exec.Command` 无 context 超时,死循环文档永久挂住 goroutine;无并发信号量可被 fork-bomb。
**修复**:
- `exec.CommandContext` + `context.WithTimeout(30s)`;
- `chan struct{}` 限并发 2~4;
- 先查 `typst_cache` 表;
- 临时文件 `0600` 且放私有目录。

### 10. typst.go:67 `cmd.Env = os.Environ()` 泄露密钥给子进程
**修复**:白名单传 `PATH`/`HOME`/`TYPST_*`。

## P2 — 规划(代码质量 / 性能 / 工程化)

### 11. ratelimit map 永不主动清理 — `internal/auth/ratelimit/ratelimit.go`
`failures`/`lockouts` 仅在被再次访问时 `cleanOld`,过期或一次性 key 永不删除。攻击者用大量随机 `(username, ip)` 即可撑大内存 → DoS。
**修复**:后台 goroutine 定期清理,或改 TTL map。

### 12. ratelimit 全内存,多实例失效
当前单实例可接受;水平扩展时改 Redis。低优先级。

### 13. DB 连接缺超时与空闲回收 — `internal/core/db/db.go:20,38,46-48`
**修复**:DSN 加 `readTimeout=30s&writeTimeout=30s`;补 `db.SetConnMaxIdleTime(5 * time.Minute)`。

### 14. verifyCaptcha 注释"constant-time"但用 `==` — `internal/api/auth.go:51-59`
注释声称恒定时间,实现是 `strings.TrimSpace(input) == stored`。值域小、单次使用实际可利用性有限,但注释误导。
**修复**:用已有 `crypto.go:constantTimeCompare`,更正注释。

### 15. sanitizeNext 残留开放重定向 — `internal/api/auth.go:184-189`
未拦 `/\evil.com`、控制字符、`%2F`。
**修复**:`url.Parse` 后校验 `Host=="" && Scheme==""` 且首字符 `/`。

### 16. 全文搜索 `q + "*"` 未转义 — `internal/content/articles.go:193`
MySQL 布尔模式 `+ - * < > ( ) "` 为操作符,用户输入 `"`/`-` 致语法错误或非预期结果;空查询变 `"*"` 报错。
**修复**:转义特殊字符或改 `IN NATURAL LANGUAGE MODE`;空查询拦截。

### 17. 列表接口 `SELECT content` 全量返回 LONGTEXT — `content/articles.go:48-60, 157-159`
列表/首页"最近"JSON 含每篇全文,带宽浪费明显。
**修复**:`LEFT(content, 200) AS excerpt` 或新增摘要字段,详情才返回全文。

### 18. config.go loadYAML 整体覆盖丢默认 — `internal/config/config.go:118-123`
`c.MySQL = raw.MySQL` 整体替换,yaml 未写 `pool` 时 `Pool` 被置零(MinSize=0、MaxSize=0),连接池失效。
**修复**:逐字段合并。

### 19. bcrypt 72 字节静默截断 — `internal/auth/password/password.go:47-51`
`ValidateStrength` 允许 128 字节,但 bcrypt 仅用前 72 → 不同密码 hash 碰撞。
**修复**:上界改 72 字节或显式截断说明。

### 20. 重复判重用字符串匹配 — `api/articles.go:131`、`admin.go:80`
`strings.Contains(err.Error(), "Duplicate")` 依赖错误文本。
**修复**:`errors.As` + `mysqlErr.Number == 1062`。

### 21. 全文搜索按 created_at 而非相关性排序 — `content/articles.go:208`
**修复**:`ORDER BY MATCH(title, content) AGAINST(?) DESC`。

### 22. 聚合层错误被吞(已确认 `建议.md §2.3`)— `api/articles.go:65-67, 80`
`comments, _ :=`、`lineComments, _ :=`、`lineCounts, _ :=`、`rating, _ :=` 共 4 处。
**修复**:记日志(含 article id + err),前端区分"文章失败"与"评论失败"。

### 23. middleware.go:36 PersistSession error 被吞
**修复**:失败 `log.Printf`,便于排查"莫名掉登录"。

### 24. 全项目无测试 / 无 CI — 严重工程化缺口
无 `*_test.go`,无 `.github/workflows/`。
**修复**:
- 关键单测:`password`(强度)、`ratelimit`(窗口/锁定)、`session`(CSRF 恒定时间/过期)、`parsers`(Wikidot/BBCode 种子文章 HTML 比对回归——`重写.md` §3.5/§9 已要求);
- GitHub Action:`go vet` + `go test` + `golangci-lint` + 前端 `next lint` + `tsc`。

## P3 — 改进(架构 / 可维护性)

- **25. schema 13 表 vs 设计 12 表**:`typst_cache` 多出合理,回写设计文档。
- **26. 缺可观测性**:日志全 `log.Printf` 非结构化、无 request id、无 metrics。切 `log/slog` + 请求 id + 基础指标。
- **27. 缺 HTTP 安全响应头**:CSP/HSTS/X-Frame-Options/X-Content-Type-Options/Referrer-Policy。加统一中间件。
- **28. 详情聚合可加 ETag / 短 TTL 缓存**降低 DB 压力,内容更新时失效。
- **29. listArticles 分页无上限**:`OFFSET` 巨大时慢,改 keyset 分页。
- **30. int64ToString 手写**(`auth.go:227`):用 `strconv.FormatInt`。
- **31. goldmark indirect**(已确认):`go mod tidy`。

## 推荐实施顺序(分 4 批,每批可单独审阅)

| 批次 | 范围 | 预计工时 | 内容 |
|---|---|---|---|
| 第 1 批 | P0 安全 | 1-2h | 1、2、3。先复核 `user.go`,修日志泄密、补 `json:"-"`、createUser 禁 owner |
| 第 2 批 | P1 安全/正确性 | 3-4h | 4-10。CHECK 约束、IP 信任、rand error、建表 fatal、typst 超时/并发/缓存 |
| 第 3 批 | P2 质量/性能 | 4-6h | 11、13、16-23。ratelimit 清理、DB 超时、搜索转义、列表瘦身、判重错误码、聚合错误日志 |
| 第 4 批 | 工程化 | 6-8h | 24(测试+CI)、26-28(可观测性+安全头+缓存)。其余 P3 与 `建议.md` 已知项按需穿插 |

附录 A 中成本 <1h 的项(`静态资源服务`、`/api/site 读 settings`、`getArticle 类型校验`、`DOMPurify`、`captcha 随机源`、`requireLogin 应用`、`前端 Dockerfile+compose`、`Nginx 配置`、`SessionSecret 生产强制`)可并入第 2-3 批顺手处理。

每批改完跑 `go vet ./...` + `go test ./...` + `go build ./...`,前端跑 `npm run lint && npm run build`。
涉及 schema 变更(CHECK 约束)需提供"既有数据清洗 + 建表语句更新"两步。

### A. 用 docker compose(推荐,贴近生产)

```bash
# 1. 启动 mysql + backend + frontend
cd /Volumes/TiPro7000/Projects.localized/Go/GoKYCH

# 2. 等几秒看健康(应用启动 + schema 创建 + admin seed)

# 期望: {"db":"ok","status":"ok"}

curl -s http://localhost:8000/api/site | head -c 200
# 期望: JSON 含 site.title / appearance / features / subsite_links

# 4. 创建文章(需要 admin)
CSRF=$(curl -sc /tmp/c.txt http://localhost:8000/api/auth/csrf | python3 -c "import sys,json;print(json.load(sys.stdin)['csrf_token'])")
# 登录(admin/admin123)
curl -sb /tmp/c.txt -c /tmp/c.txt \
  -H "X-CSRF-Token: $CSRF" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123","captcha":"1","csrf_token":"'"$CSRF"'","next":"/admin"}' \
  http://localhost:8000/api/auth/login
# 创建一篇 md 文章
curl -sb /tmp/c.txt -c /tmp/c.txt \
  -H "X-CSRF-Token: $CSRF" \
  -H "Content-Type: application/json" \
  -d '{"slug":"hello","title":"Hello World","content":"# hi\n\nfirst post","tags":["test"]}' \
  "http://localhost:8000/api/articles?type=md"

# 5. 访问首页确认渲染
curl -s http://localhost:3000/ | grep -i "hello"

# 6. 评论验证 requireLogin(应该 401)
curl -s -X POST http://localhost:8000/api/articles/md/hello/comments \
  -H "Content-Type: application/json" -d '{"content":"hi"}'
# 期望: {"error":"请先登录。"}

# 7. 文件上传 smoke test
echo "hello world" > /tmp/test.txt
curl -sb /tmp/c.txt -c /tmp/c.txt \
  -H "X-CSRF-Token: $CSRF" \
  -F "file=@/tmp/test.txt" \
  http://localhost:8000/api/admin/files
# 期望: {"filename":"...","url":"/uploads/...","status":"ok"}

curl -I http://localhost:8000/uploads/$(ls -t /Volumes/TiPro7000/Projects.localized/Go/GoKYCH/data/uploads/ | head -1)
# 期望:Cache-Control: public, max-age=3600

# 8. XSS regression(后端已经过测试,前端用浏览器手动验证)
# 在 admin 文章编辑器输入:
#   [[link|http://evil.com " onmouseover="alert(1)"]]
# 保存后查看文章页,浏览器 console 应该无任何 alert

# 9. 停服
```

## 🐛 Smoke test 中如发现问题

我 4 阶段改动涉及 25+ 个文件,**单一测试是覆盖率不是 0 错误的保证**。如果在 smoke test 中发现行为异常:

1. **看 backend log**: `docker compose logs backend`
2. **看浏览器 console**: F12 → Console
3. **看 frontend log**: `docker compose logs frontend` 或 `npm run dev` 终端输出

如发现 bug,我可以快速定位修。常见高风险点:
- 文件上传(MIME allowlist / 大小)
- 评论/评分 requireLogin(可能影响现有未登录用户)
- /api/site 读 settings.yml(如果 yml 格式坏了会回退 default)
- DOMPurify(dynamic import 在首次渲染可能有闪烁)

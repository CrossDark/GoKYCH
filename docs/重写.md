# 跨越晨昏 — PyKYCH → GoKYCH 重写方案

> 源项目：`../PyKYCH`（Python + LiHiL + Jinja2 + aiomysql，约 11.9k 行）
> 目标项目：`GoKYCH`（**前后端分离**：Go + Gin JSON API ＋ React + Next.js）
> 本文是**实施前的方案设计**，不是已完成记录。

---

## 0. TL;DR

将 PyKYCH 重写为**前后端分离**架构：

- **后端**：Go + Gin，纯 JSON API。Markdown/Wikidot/BBCode 在后端渲染成 HTML 字符串放进 JSON 返回。
- **前端**：React + Next.js（App Router，SSG/SSR），重写全部页面，**保持对外 URL 与浏览器访问体验不变**。
- **数据库**：全面重构——5 张同构文章表合并为 1 张、关联表改 `article_id` 外键、删 UNION 视图（全新建库，丢弃现有数据）。
- **密码**：bcrypt（不再保留 PBKDF2 格式）。
- **内容类型**：保留 md/wikidot/html/bbcode/typst 五类（HTML 为纯手写，**放弃外部抓取**）。
- **扩展系统**：插件、主题首版暂缓。
- **API 可重新设计**：前端 fetch 契约无需兼容 PyKYCH，按 RESTful 干净设计。

> 用户感知约束：打开浏览器访问网站的体验（URL 结构、页面外观、交互）基本不变；底层 API 端点、请求契约可自由重构。

## 1. 现状摸底（来自 PyKYCH）

### 1.1 规模

| 维度 | 数量 |
|------|------|

| 静态资源 | 仅 `img/`（logo/favicon）；**CSS 全部内联在 `base.html`（1011 行）**，无独立 JS/CSS 文件 |
| 前端交互 | SSR 为主，少量 `fetch()`（评分、行评论、passkey、用户菜单） |

### 1.2 Python 版技术债（重构消除对象）

| 技术债 | 成因 | 重构后 |
|--------|------|--------|
| 5 张同构文章表 | 历史逐类型建表 | 合并为 1 张 `articles` 表 + `type` 字段 |
| `VW_ALL_ARTICLES` UNION 视图 | 跨类型查询要 UNION | 单表查询，视图删除 |
| 关联表 `(article_type, article_slug)` 复合键 | 无统一文章 id | 改用 `article_id` 外键 |
| 详情页多次往返查 tags/comments/rating | 各自独立查询 | **后端单接口聚合**返回 |
| 搜索 5 路 UNION ALL | 同上 | 单表 `MATCH ... AGAINST` |
| PBKDF2 自定义格式 + NFC + 手写解析 | 兼容旧哈希 | bcrypt |
| `_migrate_*` 系列迁移函数 | 在线平滑升级 | 全新库，建表即终态，无迁移 |
| 详情页 N+1 查询 | 评论/评分/标签分批加载 | 聚合接口一次取齐 |

### 1.3 Python 版关键依赖 → Go/JS 对照

| 能力 | Python 实现 | Go / JS 对应 |
|------|------------|------------|
| Web 框架 | LiHiL (ASGI) | **Gin**（后端 API） |
| 页面渲染 | Jinja2 (SSR) | **Next.js**（前端） |
| 数据库 | aiomysql 异步池 | **database/sql + go-sql-driver/mysql** |
| Markdown | python-markdown + 5 扩展 | **Goldmark + 扩展**（后端渲染） |
| Wikidot/BBCode 解析 | 自写正则 | Go 重写（后端） |
| Typst 渲染 | subprocess 调 typst CLI | `os/exec` 调 typst CLI（后端） |
| 密码哈希 | PBKDF2-SHA256 | **bcrypt** |
| 会话 | Starlette SessionMiddleware（签名 Cookie） | **gorilla/sessions**（cookie store） |
| CSRF | itsdangerous 签名 token | 自写（session token + 恒定时间比较） |
| WebAuthn | cryptography + 自写 CBOR | **go-webauthn/webauthn** |
| YAML | PyYAML | **yaml.v3** |

## 2. 总体架构

```
                         浏览器
                           │
                  ┌────────▼─────────┐
                  │   Next.js 前端    │  SSR/SSG，React 组件
                  │   (端口 3000)     │  全局 CSS（提取自 base.html）
                  └────────┬─────────┘
                           │  /api/*  (同源，Cookie 自动携带)
                  ┌────────▼─────────┐
                  │   Gin 后端 API    │  纯 JSON
                  │   (端口 8000)     │  内容渲染→HTML 字符串
                  └────────┬─────────┘
                           │
                  ┌────────▼─────────┐
                  │     MySQL 8      │  12 张表（重构后）
                  └──────────────────┘
```

**部署形态**：生产用 Nginx 把 `/api/*`、`/static/*`、`/avatars/*` 反代到 Go，其余路径交给 Next.js（或 Next.js standalone）。开发时 Next.js dev server 通过 `rewrites` 把 `/api/*` 代理到 `localhost:8000`。

**同源 Cookie 鉴权**：前后端同域，会话用 httpOnly Cookie（gorilla/sessions），天然防 XSS 窃取，无需前端管理 token。这是分离架构下最简且最安全的方案。

### 3.3 数据库 Schema（全面重构，12 表）

全新建库，丢弃旧数据。建表即终态，无迁移函数。

```sql
-- ═══ 统一文章表（合并 5 张）═══
CREATE TABLE articles (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    type        ENUM('md','wikidot','html','bbcode','typst') NOT NULL,
    slug        VARCHAR(255) NOT NULL,
    title       VARCHAR(255) NOT NULL,
    content     LONGTEXT NOT NULL,            -- 原始源码（不存 HTML，按需渲染）
    author_id   INT DEFAULT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uq_type_slug (type, slug),
    INDEX idx_type_created (type, created_at),
    INDEX idx_author (author_id),
    FULLTEXT INDEX ft_title_content (title, content)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE users (
    id            INT AUTO_INCREMENT PRIMARY KEY,
    username      VARCHAR(64) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,      -- bcrypt（$2b$...）
    nickname      VARCHAR(128) NOT NULL DEFAULT '',
    role          ENUM('user','admin','owner') NOT NULL DEFAULT 'user',
    avatar        VARCHAR(255) DEFAULT NULL,
    bio           VARCHAR(500) DEFAULT '',
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE tags (
    id   INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(64) UNIQUE NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE article_tags (
    article_id INT NOT NULL,
    tag_id     INT NOT NULL,
    PRIMARY KEY (article_id, tag_id),
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id)     REFERENCES tags(id)     ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 评论（全文 + 行评论合并，line_number 区分）
CREATE TABLE comments (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    article_id  INT NOT NULL,
    line_number INT DEFAULT NULL,             -- NULL=全文；非空=该行短评(≤20字)
    author_name VARCHAR(128) NOT NULL DEFAULT '匿名',
    content     VARCHAR(500) NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE,
    INDEX idx_article_line (article_id, line_number)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE ratings (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    article_id  INT NOT NULL,
    author_name VARCHAR(128) NOT NULL,
    score       DECIMAL(4,2) NOT NULL,        -- 范围 [-1.00, 1.00]
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uq_user_article (article_id, author_name),
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE,
    INDEX idx_author_name (author_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE webauthn_credentials (
    id            INT AUTO_INCREMENT PRIMARY KEY,
    user_id       INT NOT NULL,
    credential_id VARBINARY(1024) NOT NULL UNIQUE,
    public_key    BLOB NOT NULL,
    sign_count    BIGINT DEFAULT 0,
    transports    VARCHAR(255) DEFAULT '',
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE subsite_links (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL, url VARCHAR(1024) NOT NULL,
    description VARCHAR(512) DEFAULT '', sort_order INT NOT NULL DEFAULT 0,
    INDEX idx_sort (sort_order)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE featured_articles (
    id INT AUTO_INCREMENT PRIMARY KEY,
    article_id INT NOT NULL, sort_order INT NOT NULL DEFAULT 0,
    UNIQUE KEY uq_featured (article_id),
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE,
    INDEX idx_sort (sort_order)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE notifications (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(255) NOT NULL, content TEXT NOT NULL,
    is_important TINYINT(1) NOT NULL DEFAULT 0,
    is_active TINYINT(1) NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_active_important (is_active, is_important)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE static_files (
    id INT AUTO_INCREMENT PRIMARY KEY,
    filename VARCHAR(255) UNIQUE NOT NULL, original_name VARCHAR(255) NOT NULL,
    file_path VARCHAR(512) NOT NULL, file_size BIGINT NOT NULL DEFAULT 0,
    mime_type VARCHAR(128) DEFAULT 'application/octet-stream',
    uploaded_by INT DEFAULT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_uploaded_by (uploaded_by)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE typst_files (
    id INT AUTO_INCREMENT PRIMARY KEY,
    article_id INT NOT NULL, filename VARCHAR(255) NOT NULL, content LONGTEXT NOT NULL,
    UNIQUE KEY uq_article_file (article_id, filename),
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE typst_cache (
    id INT AUTO_INCREMENT PRIMARY KEY,
    article_id INT NOT NULL UNIQUE,
    html_content LONGTEXT NOT NULL, pdf_content LONGBLOB NOT NULL,
    dependencies TEXT DEFAULT NULL,
    compiled_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (article_id) REFERENCES articles(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**15 → 12 表**：删 pages/html_pages/bbcode_pages/typst_pages（合入 articles）、line_comments（合入 comments）、`VW_ALL_ARTICLES` 视图、全部 `_migrate_*` 函数。评分范围统一为 `[-1.00, 1.00]`（修正 PyKYCH 中 api.py 注释误写 "0-5"）。

### 3.4 认证与会话

- **会话**：gorilla/sessions cookie store，密钥来自 `SESSION_SECRET`。会话键 `user_id` / `login_time` / `last_activity` / `csrf_token` / `captcha_answer`。24h 空闲过期。生产 Secure + HttpOnly + SameSite=Lax。
- **CSRF**：登录时生成 64 字符 hex token 入 session；所有改状态 API（POST/PUT/DELETE）校验 `X-CSRF-Token` 头或表单字段，`subtle.ConstantTimeCompare`。
- **速率限制**：登录每「用户名+IP」5 次/分，连续 10 次锁 15 分钟；`check-passkey` 每 IP 每分 10 次。
- **WebAuthn**：用 go-webauthn 库，凭据关联 `user_id`。**首版可先禁用 passkey 登录**（密码链路先稳），passkey 进 v1.1。
- **权限中间件**：`RequireLogin` / `RequireAdmin` / `RequireOwner`，未通过返回 401/403 JSON（前端据状态码跳登录）。
- **密码强度**：照搬 `validate_password_strength`（≥8 位、含大小写+数字、无空白）。

### 3.5 内容渲染（后端）

`internal/render` 统一入口：
```go
func ArticleHTML(typ ArticleType, content string) template.HTML {
    switch typ {
    case TypeMarkdown: return markdown.Render(content)
    case TypeWikidot:  return wikidot.Render(content)
    case TypeBBCode:   return bbcode.Render(content)
    case TypeHTML:     return template.HTML(content)   // 原样（管理员可信）
    case TypeTypst:    return typst.Render(content)     // 编译→HTML
    }
}
```
- **Markdown**：Goldmark + table/strikethrough/TOC；admonition（`!!! note`）预处理或 ast 插件。
- **Wikidot**：1:1 移植 Python 版 18 个预编译正则（占位→块→行内→还原）。用种子文章做 HTML 比对回归。
- **BBCode**：1:1 移植正则替换。
- **Typst**：`os/exec` 调 typst CLI + 临时目录 + `typst_cache` 表（关联 `article_id`）。
- 返回的 HTML 由可信管理员内容产生，前端注入；可加 DOMPurify 作纵深防御。

### 3.6 API 设计（RESTful，干净重构）

> 前端 fetch 契约无需兼容 PyKYCH，按资源化设计。`{type} ∈ {md,wikidot,html,bbcode,typst}`，对外 URL 用类型前缀。

**聚合优化**：详情页一个接口返回文章+标签+评论+评分，消除原版 N 次往返。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/site` | 站点设置（标题/副标题/ICP/外观开关），前端全局用 |
| GET | `/api/home` | 首页聚合：子站点链接 + 推荐文章 + 重要通知 |
| GET | `/api/auth/me` | 当前用户（null=未登录） |
| POST | `/api/auth/login` | `{username,password,captcha,csrf}` → `{user}` |
| POST | `/api/auth/logout` | |
| POST | `/api/auth/register` | （若开放注册） |
| * | `/api/auth/webauthn/*` | passkey 注册/登录（v1.1） |
| GET | `/api/articles?type=&page=` | 列表（含标签，批量查避免 N+1） |
| GET | `/api/articles/{type}/{slug}` | **详情聚合**：`{article:{...,html,tags,can_edit}, comments, line_comments, rating}` |
| POST | `/api/articles` | 新建（admin）`{type,slug,title,content}` |
| PUT | `/api/articles/{type}/{slug}` | 编辑 `{title,content}` |
| DELETE | `/api/articles/{type}/{slug}` | 删除（CASCADE 清关联） |
| GET/POST | `/api/articles/{type}/{slug}/comments` | 全文评论 |
| GET/POST | `/api/articles/{type}/{slug}/line-comments` | 行评论（≤20字） |
| GET/POST/DELETE | `/api/articles/{type}/{slug}/rating` | 评分 `[-1,1]` |
| GET | `/api/search?q=&page=` | 全文搜索（单表 MATCH AGAINST） |
| GET | `/api/labels` | 标签聚合（含文章数） |
| GET | `/api/labels/{tag}` | 该标签下文章 |
| GET | `/api/notifications` | 活跃通知 |
| GET/POST/DELETE | `/api/files` | 上传文件管理 |
| * | `/api/admin/*` | 管理后台 CRUD（文章/标签/通知/文件/用户/子站点/推荐/设置/资料），全部 RequireAdmin |
| GET | `/static/uploads/{f}` `/static/img/{f}` `/avatars/{f}` | 静态资源（路径遍历防护，`filepath.Clean`+前缀校验） |

**默认管理员**：首次启动 `users` 表空时插入 `admin/admin123`（owner，bcrypt）。

## 4. 前端方案（React + Next.js）

### 4.1 技术选型

| 项 | 选型 |
|----|------|
| 框架 | **Next.js 14+ App Router**（SSG 为主 + 需登录页 SSR/客户端） |

### 4.3 路由与 URL（保持对外一致）

完全复刻 PyKYCH 的 URL 结构，保证书签/外链/SEO 不变：

| URL | 页面 |
|-----|------|
| `/` | 首页 |
| `/md` `/md/{slug}` | Markdown 列表/详情 |
| `/wikidot` `/wikidot/{slug}` | 同上 |
| `/html` `/html/{slug}` | HTML（本地手写） |
| `/bbcode` `/bbcode/{slug}` | BBCode |
| `/typst` `/typst/{slug}` | Typst |
| `/labels` `/labels/{tag}` | 标签 |
| `/search` | 搜索 |
| `/about` | 关于 |
| `/auth/login` | 登录 |
| `/admin` 及子页 | 管理后台 |

### 4.4 关键交互复刻

- **行评论**：详情页文章按行渲染，每行左侧浮标显示评论数，点击展开。`LineComments` 客户端组件调 `/api/articles/{type}/{slug}/line-comments`。
- **评分**：`RatingWidget` 调 `/api/articles/{type}/{slug}/rating`，已评分可撤销。
- **暗黑模式**：next-themes，`attribute="data-theme"`，与原 CSS 变量（`[data-theme="dark"]`）无缝衔接；无闪烁。
- **登录**：数学验证码 + CSRF，登录后跳 `next`（防开放重定向）。
- **用户菜单**：Header 调 `/api/auth/me` 显示头像/昵称。

### 4.5 样式迁移

`base.html` 的 1011 行内联 CSS（含 CSS 变量、暗黑模式、响应式）**整块提取到 `globals.css`**，几乎不动。HTML 结构拆成 React 组件，class 名保持原样，样式直接生效。这是"用户感知不变"的关键，也是降低前端工作量的杠杆点。

## 5. 部署

### 5.1 Docker（多服务）

```yaml
# docker-compose.yml（精简示意）
services:
  mysql: ...              # 复用 PyKYCH 的 MySQL 8.0（utf8mb4，3307）
  backend: # Go
    build: ../Dockerfile
    env: { DB_*, SESSION_SECRET }
    ports: [ "8000:8000" ]
    volumes: [ app_data:/app/data ]
  frontend: # Next.js standalone
    build: ./web/Dockerfile
    env: { API_BASE=http://backend:8000 }
    ports: [ "3000:3000" ]
    depends_on: [ backend ]
```

- **后端 Dockerfile**：多阶段，`golang:1.26` 构建 → `alpine` 运行 + typst CLI。
- **前端 Dockerfile**：`node:20-alpine` 构建（`next build` standalone） → 精简运行镜像。
- **生产 Nginx**：`/api/*` `/static/*` `/avatars/*` → Go；其余 → Next.js；统一 HTTPS。

### 5.2 开发模式

Next.js dev（3000）+ Go（8000）+ MySQL（3307）。`web/next.config.js` 用 `rewrites` 把 `/api/*` 代理到 `localhost:8000`，Cookie 同源自动携带。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Wikidot/BBCode 正则移植出错 | 渲染异常 | 用种子文章做 HTML 比对回归 |
| `base.html` CSS 提取遗漏 | 样式偏差 | 整块搬 `globals.css`，class 名不变，逐页对比 |
| 分离后 Cookie 跨域问题 | 登录态丢失 | 同源部署 + Next rewrites；生产 Nginx 同域 |
| SSR/SSG 与登录态交互复杂 | 私有页闪烁/错乱 | 公开页 SSG，登录态用客户端组件 + `/api/auth/me` |
| WebAuthn 协议差异 | passkey 不可用 | 首版禁用 passkey，进 v1.1 |
| 前端工作量大（32 页重写） | 工期长 | CSS 复用降难度；按里程碑分批；后端先行可并行 |
| 外键 CASCADE | 删文章级联删评论 | 与原版删除逻辑一致，符合预期 |

## 10. 不做什么（首版明确排除）

- ❌ 插件系统（`plugins_sys`）动态加载——留接口占位。
- ❌ 主题系统（`themes_sys`）模板覆盖——单一主题，`globals.css`。
- ❌ 数据迁移/旧库兼容——全新建库，丢弃现有数据。
- ❌ PBKDF2 兼容——改 bcrypt。
- ❌ 外部 HTML 抓取——HTML 类型仅纯手写（抓取功能 PyKYCH 代码本已删除）。
- ❌ 替换 typst——仍调外部 CLI。
- ❌ 兼容旧 API fetch 契约——API 重新设计。

这些是**有意识的范围控制**，目的是让网站尽快以更干净的架构在前后端分离形态下跑起来。

# 配置说明

GoKYCH 的配置采用**三级优先级**机制，高优先级覆盖低优先级：

```
环境变量 > YAML 配置文件 > 默认值
```

## 环境变量（.env 文件）

在项目根目录创建 `.env` 文件，参考 `.env.example`：

```bash
cp .env.example .env
```

### 数据库配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DB_HOST` | `localhost` | MySQL 主机地址 |
| `DB_PORT` | `3306` | MySQL 端口 |
| `DB_USER` | `gokych` | 数据库用户名 |
| `DB_PASSWORD` | `gokych` | 数据库密码 |
| `DB_NAME` | `gokych` | 数据库名称 |
| `DB_CHARSET` | `utf8mb4` | 字符集 |
| `DB_POOL_MIN` | `5` | 连接池最小连接数 |
| `DB_POOL_MAX` | `25` | 连接池最大连接数 |
| `DB_POOL_RECYCLE` | `3600` | 连接回收时间（秒） |

### 应用配置

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `APP_PORT` | `8000` | HTTP 服务端口 |
| `GIN_MODE` | `debug` | Gin 运行模式：`debug` / `release` / `test` |
| `SESSION_SECRET` | `change-me-to-a-random-string` | 会话加密密钥（**生产环境务必修改**，建议 32+ 字节随机串） |
| `ADMIN_USERNAME` | `admin` | 默认管理员用户名 |
| `ADMIN_PASSWORD` | `admin123` | 默认管理员密码（仅首次初始化时生效，**启动后立刻修改**） |
| `DATA_DIR` | `data` | 数据目录路径 |
| `PUBLIC_URL` | _(空)_ | 后端对外的公开 URL，用于跨域场景拼接静态资源绝对路径 |
| `CORS_ALLOWED_ORIGINS` | _(空)_ | 逗号分隔的允许跨域来源（如 `https://eo.example.com`） |
| `SESSION_COOKIE_DOMAIN` | _(空)_ | Cookie 域名，跨子域部署时设为 `.example.com` |
| `TRUSTED_PROXIES` | _(空)_ | 可信代理 IP/CIDR，逗号分隔。空值表示不信任任何代理，仅使用 RemoteAddr |
| `APP_DOMAIN` | _(空)_ | Passkey 依赖域名。空则禁用 Passkey |

## YAML 配置文件

### 数据库配置

数据库配置可通过 YAML 文件指定，路径为 `$DATA_DIR/settings/db.yaml`：

```yaml
mysql:
  host: localhost
  port: 3306
  user: gokych
  password: gokych
  database: gokych
  charset: utf8mb4
  pool:
    minsize: 5
    maxsize: 25
    pool_recycle: 3600
```

配置模板位于 `configs/db.yaml.example`。

### 站点设置

站点级别的设置存储在 `$DATA_DIR/settings/settings.yml`，包含以下三个 section：

- `site` — 站点元数据（标题、ICP备案、favicon 等）
- `appearance` — 外观设置（主题、配色等）
- `features` — 功能开关（见下节）

该文件由应用自动创建和维护，可通过管理后台 API 修改：

```
GET /api/admin/settings   — 查看
PUT /api/admin/settings   — 修改（需 owner 角色）
```

#### features 功能开关

| 开关 | 默认值 | 说明 |
|------|--------|------|
| `enable_comments` | `true` | 启用全文评论 |
| `enable_dark_mode` | `true` | 启用暗色模式切换 |
| `enable_search` | `true` | 启用全文搜索 |
| `enable_tags_sidebar` | `true` | 启用标签侧边栏 |
| `posts_per_page` | `10` | 每页文章数 |
| `allow_all_edit` | `false` | **站长专属**：开启后所有已登录用户可编辑/删除任意文章 |

## Cloudflare Workers 配置（wrangler.jsonc）

前端部署到 Cloudflare Workers 时，配置文件位于 `web/wrangler.jsonc`：

- `name` 和 `services[0].service` **必须完全一致**，且必须与 Cloudflare Dashboard 中创建的 Worker 名称完全匹配，否则会出现 10143 错误（Service binding references Worker which was not found）
- Cloudflare Workers Builds（Git 连接部署）会自动用 Dashboard 中的 Worker 名称覆盖 `name` 字段，但**不会覆盖** `services[].service`，因此两个字段都必须显式设置为正确的名称
- 如需自定义 Worker 名称，请同时修改这两个字段

示例：
```jsonc
{
  "name": "your-worker-name",
  "services": [
    { "binding": "WORKER_SELF_REFERENCE", "service": "your-worker-name" }
  ]
}
```

## 前端构建环境变量

构建 Next.js 前端时可使用以下环境变量：

| 变量 | 说明 |
|------|------|
| `NEXT_PUBLIC_API_BASE_URL` | **生产构建必需**，指向后端 API 地址（如 `https://api.example.com`）。浏览器端跨域请求使用此地址。开发模式下会自动回退到 `localhost:8000`。 |
| `STANDALONE=1` | Docker 构建时使用。启用 Next.js standalone 输出模式（大幅减小镜像体积），并跳过 `NEXT_PUBLIC_API_BASE_URL` 的必填检查（容器内通过 docker 网络直接访问后端）。 |

## 数据目录结构

`DATA_DIR`（默认 `data`）下包含以下子目录，应用启动时自动创建：

```
data/
├── settings/    # 配置文件（db.yaml, settings.yml）
├── avatars/     # 用户头像上传
├── uploads/     # 文章图片/文件上传
├── plugins/     # 插件目录
├── themes/      # 主题文件
└── typst/       # Typst 编译临时文件
```

## 配置优先级示例

假设 `db.yaml` 中 `host: yaml-host`，`.env` 中 `DB_HOST=env-host`，则最终使用 `env-host`。

如果只设置了 `db.yaml` 的 `host`，环境变量未设置，则使用 `yaml-host`。

如果两者都未设置，则使用默认值 `localhost`。

## 生产环境建议

1. **修改 `SESSION_SECRET`** 为随机长字符串（32+ 字节）
2. **修改默认管理员密码** 或首次登录后立即修改
3. **设置 `GIN_MODE=release`** 关闭调试模式
4. **配置 `TRUSTED_PROXIES`** 如使用反向代理
5. **使用强数据库密码** 并限制数据库访问来源
6. **配置 `PUBLIC_URL` 和 `CORS_ALLOWED_ORIGINS`** 如前后端分离部署
7. **配置 `APP_DOMAIN`** 以启用 Passkey 无密码登录

# 架构概览

## 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| **后端** | Go 1.26+ (1.26.4) + Gin | RESTful API 服务器 |
| **前端** | Next.js 16 + React 19 | SSR/ISR 前端应用（App Router） |
| **数据库** | MySQL 8.0 | 主数据存储 |
| **容器化** | Docker + Docker Compose | 开发与 Docker standalone 部署 |

### 后端核心依赖

- **Gin** — HTTP Web 框架
- **go-sql-driver/mysql** — MySQL 驱动
- **goldmark** — Markdown 渲染
- **bluemonday** — HTML 安全清洗
- **gorilla/sessions** — 加密 Cookie 会话管理
- **golang.org/x/crypto** — 密码哈希（bcrypt）
- **go-webauthn/webauthn** — Passkey 无密码登录
- **gopkg.in/yaml.v3** — YAML 配置解析

### 前端核心依赖

- **next-themes** — 主题切换（暗色/亮色）
- **@opennextjs/cloudflare** — Cloudflare Workers 部署适配器
- **marked / dompurify / katex / mermaid** — 客户端 Markdown 渲染增强
- **TypeScript** — 类型安全

## 权限模型

三级角色体系：

| 角色 | 权限 |
|------|------|
| **owner（站长）** | 拥有所有权限，可切换 `allow_all_edit` 开关 |
| **admin（管理员）** | 管理所有文章/用户/评论/站点设置 |
| **user（普通用户）** | 可创建文章；默认仅能编辑/删除自己的文章 |

站长专属开关 `allow_all_edit`：开启后所有已登录用户可编辑/删除任意文章。

相关文档：[[API-接口文档]]、[[配置说明]]

## 前端部署选项

前端 Next.js 应用支持三种部署方式：

| 方式 | 说明 | 构建命令 |
|------|------|----------|
| **EdgeOne Makers** | 推荐国内使用，自动检测 Next.js 构建 | `next build` |
| **Cloudflare Workers** | 使用 `@opennextjs/cloudflare` 适配器 | `npm run cf:build && npm run cf:deploy` |
| **Docker standalone** | 传统 Node.js 服务器，设 `STANDALONE=1` | `next build`（输出 `.next/standalone`） |

跨域部署时需设置 `NEXT_PUBLIC_API_BASE_URL` 指向 Go 后端地址，前端 API 客户端会自动携带 Cookie。

相关文档：[[部署指南]]

## Server 结构体

`internal/api/server.go` 中的 `Server` 结构体通过依赖注入承载所有共享依赖：

- **DB** — `*sql.DB` 数据库连接池
- **sessions** — `*session.Manager` 会话管理器
- **limiter** — `*ratelimit.Limiter` 登录速率限制器
- **Metrics** — `*metrics.Metrics` 运行指标
- **DataDir** — 运行时数据目录路径
- **Typst** — `*typst.Worker` Typst 编译工作池
- **Version** — 构建版本字符串（通过 `-ldflags` 注入）
- **PublicURL** — 后端对外绝对 URL（用于跨-origin 资源路径拼接）
- **CORSAllowedOrigins** — CORS 允许的跨域来源白名单
- **webAuthn** — Passkey/WebAuthn 配置（RPID/RPName/Origins），懒加载初始化

## 启动流程

```
main()
  ├── 1. config.Load()           — 加载配置（默认值 → .env → YAML → 环境变量）
  ├── 2. cfg.EnsureDataDirs()    — 创建数据目录
  ├── 3. settings.Ensure()       — 确保默认 settings.yml 存在
  ├── 4. coredb.Init(cfg)        — 初始化 MySQL 连接池
  ├── 5. schema.Init(db)         — 执行 DDL 建表
  ├── 6. schema.SeedAdmin()      — 种子默认管理员
  ├── 7. session.New()           — 创建会话管理器
  ├── 8. ratelimit.New()         — 创建速率限制器
  ├── 9. typst.NewWorker()       — 创建 Typst 编译工作池
  ├── 10. api.NewServer()        — 创建 API Server 并注入依赖
  ├── 11. srv.ConfigureWebAuthn() — 配置 Passkey
  ├── 12. srv.Setup(r)           — 注册路由
  └── 13. httpSrv.ListenAndServe — 启动 HTTP 服务（支持优雅关闭）
```

## 请求处理流程

```
客户端请求
  → 安全响应头中间件 (securityHeaders)
  → 请求 ID 中间件 (requestID)
  → 会话中间件 (sessionMiddleware)
  → 用户加载中间件 (loadUserMiddleware)
  → 路由匹配
  → [可选] CSRF 中间件 (csrfMiddleware)
  → [可选] 权限中间件 (requireAdmin / requireOwner)
  → 业务处理器
```

## 前端关键文件说明

| 文件 | 作用 |
|------|------|
| `web/lib/api/client.ts` | 统一 API 客户端：SSR 超时控制、跨域 `credentials:include`、SSR Cookie 转发（通过 `next/headers`）、请求去重 |
| `web/middleware.ts` | 全局中间件：生成每请求 CSP nonce（Web Crypto API）、设置 CSP/X-Frame-Options 等安全头，兼容 Node 与 Edge Runtime |
| `web/next.config.ts` | 条件配置：`STANDALONE=1` 时输出 standalone；生产构建校验 `NEXT_PUBLIC_API_BASE_URL`；dev 环境代理 `/api`、`/uploads` 到后端 |

## 文章内容类型

系统支持 5 种文章类型，每种使用不同的解析器渲染：

| 类型 | 路径前缀 | 解析器 | 说明 |
|------|----------|--------|------|
| Markdown | `/md/` | goldmark | 标准 Markdown |
| Wikidot | `/wikidot/` | 自研解析器 | Wikidot 语法兼容 |
| HTML | `/html/` | 直接渲染 | 原始 HTML（经 bluemonday 清洗） |
| BBCode | `/bbcode/` | 自研解析器 | 论坛风格标签 |
| Typst | `/typst/` | typst 引擎 | 排版系统，支持编译为 HTML/PDF |

# 部署指南

本文档是部署概览，详细步骤请参考 [[../docs/deployment.md]]。

---

## 架构概览

### 推荐架构（国内首选）

- **前端**：腾讯云 EdgeOne Makers（Next.js SSR 运行在边缘节点，自动构建/部署/HTTPS）
- **后端**：Go 单二进制运行在 Ubuntu VPS（nginx + systemd + MySQL 8）
- **通信**：前端 SSR 和浏览器均跨域请求 `api.yourdomain.com`，由后端 CORS 中间件处理
- **优势**：国内访问速度快，VM 上无需运行 Node.js，前端发布 = `git push`

### 备选方案

| 方案 | 适用场景 | 说明 |
|------|----------|------|
| **Cloudflare Workers**（`@opennextjs/cloudflare`） | 海外用户 | 需要 Workers Paid 计划（$5/月） |
| **Docker standalone** | 自托管/内网 | 前端用 `STANDALONE=1 npm run build` 构建，配合 nginx 反代 |

## 快速开始（本地开发）

```bash
# 1. 准备 MySQL 8.0+ 与空库
mysql -u root -p -e "CREATE DATABASE gokych DEFAULT CHARSET utf8mb4;"

# 2. 复制环境模板
cp .env.example .env
# 编辑 .env，修改 DB_USER / DB_PASSWORD / ADMIN_PASSWORD

# 3. 启动后端（自动建表 + seed 默认管理员）
go run ./cmd/gokych

# 4. 启动前端（新开终端）
cd web
npm install
npm run dev

# 访问 http://localhost:3000
# 后台：http://localhost:3000/admin → admin / admin123
```

> typst 文章需要安装 typst CLI（`brew install typst`），不装则 typst 类型文章显示"编译中"占位符。

## 生产部署：EdgeOne Makers + VPS（推荐）

### 后端一键初始化（Ubuntu 22.04/24.04）

在全新 Ubuntu VM 上，先将 `api.yourdomain.com` 和 `yourdomain.com` 的 DNS A 记录指向 VM IP，然后执行：

```bash
curl -fsSL https://raw.githubusercontent.com/CrossDark/GoKYCH/main/scripts/install-all.sh | \
  sudo bash -s -- \
    --site-name "我的网站" \
    --api-domain "api.yourdomain.com" \
    --main-domain "yourdomain.com" \
    --frontend-domain "eo.yourdomain.com" \
    --email "admin@example.com"
```

脚本自动完成：系统包安装 → MySQL 建库建用户 → 二进制下载校验 → `.env` 随机密钥 → systemd 单元 → nginx 配置 → certbot 签证书 → 备份脚本。

### 关键环境变量（后端 `.env`）

| 变量 | 说明 | 示例 |
|------|------|------|
| `PUBLIC_URL` | 后端对外绝对 URL，用于拼接静态资源绝对路径 | `https://api.yourdomain.com` |
| `CORS_ALLOWED_ORIGINS` | 允许跨域的 origin，逗号分隔（不能用 `*`） | `https://eo.yourdomain.com` |
| `SESSION_COOKIE_DOMAIN` | Session cookie 域，跨子域需设为父域（带前导点） | `.yourdomain.com` |
| `APP_DOMAIN` | Passkey RPID，前端访问域名（eTLD+1） | `https://eo.yourdomain.com` |
| `TRUSTED_PROXIES` | 信任的代理 IP（nginx 在 127.0.0.1） | `127.0.0.1` |

改完 `.env` 需 `sudo systemctl restart gokych`。

### 前端 EdgeOne Makers 配置

1. 在 EdgeOne Makers 控制台从 Git 仓库导入，Root Directory 设为 `web/`
2. **构建时环境变量（必需）**：
   - `NEXT_PUBLIC_API_BASE_URL=https://api.yourdomain.com`
3. 添加自定义域名 `eo.yourdomain.com`，按控制台给出的 CNAME 值配置 DNS
4. `git push main` → 自动构建部署（30-60 秒）

> ⚠️ `NEXT_PUBLIC_API_BASE_URL` 是构建时变量，缺失会导致构建直接失败或 API 请求静默 fallback 到 localhost。改环境变量后需重新触发部署。

## 备选：Cloudflare Workers 部署

### 快速部署

```bash
cd web/
npm install
echo "NEXT_PUBLIC_API_BASE_URL=https://api.yourdomain.com" > .env.local
npx wrangler login
npm run cf:deploy
```

或在 Cloudflare Dashboard 连接 Git 仓库自动构建：
- Root directory: `web`
- Build command: `npm run cf:build`
- Build 环境变量添加 `NEXT_PUBLIC_API_BASE_URL`

### ⚠️ 重要注意事项（10143 错误）

`web/wrangler.jsonc` 中两个字段**必须完全一致且与 Cloudflare Dashboard 中的 Worker 名称匹配**：

```jsonc
"name": "your-worker-name",
"services": [
  {
    "binding": "WORKER_SELF_REFERENCE",
    "service": "your-worker-name"  // ← 必须和上面的 name 完全相同
  }
]
```

**坑**：Cloudflare Workers Builds CI 通过 Dashboard Git 连接部署时，**只会自动覆盖 `name` 字段，不会覆盖 `services[].service`**。如果两者不匹配，部署时会出现 **10143 错误**：

> `Service binding 'WORKER_SELF_REFERENCE' references Worker 'xxx' which was not found [code: 10143]`

解决方法：确保 `name` 和 `services[0].service` 都手动设为 Dashboard 中显示的 Worker 名称，提交到 Git 后重新部署。CI 日志中的 "Failed to match Worker name" 警告会显示 CI 期望的名称，以此为准修改即可。

后端 `.env` 需添加：`CORS_ALLOWED_ORIGINS=https://your-worker-name.account.workers.dev,https://cf.yourdomain.com`

## Docker 部署

### Docker Compose（后端+MySQL）

```bash
cp .env.example .env
# 编辑 .env 修改密码
docker compose up -d
curl http://localhost:8000/api/health
```

### 前端 standalone 构建

```bash
cd web
npm install
STANDALONE=1 npm run build
npm run start
```

配合 nginx 反向代理前端 `:3000` 和后端 `:8000`，详见 [[../docs/deployment.md]]。

## 验证清单

部署后按顺序检查：

1. `curl https://api.yourdomain.com/api/health` → `{"status":"ok","db":"ok"}`
2. 浏览器打开前端首页，文章列表正常渲染（SSR 不是空壳）
3. DevTools 看到 API 请求到 `api.yourdomain.com`，Response 有 `Access-Control-Allow-Origin` 和 `Access-Control-Allow-Credentials: true`
4. 登录后台 `/admin`，创建文章、上传文件、评论评分正常
5. Passkey 登录（无痕窗口测试）正常
